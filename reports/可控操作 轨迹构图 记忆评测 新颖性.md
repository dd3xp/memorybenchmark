# 可控操作能生成轨迹图，但不是新的构图原理

核查日期：2026-10-15。论文范围限此前公开版本；依据为原文、附录和作者代码的静态审计，未运行或复现第三方实验。

详细核查记录见[空间导航与记忆笔记](<../research_notes/可控操作 轨迹构图 记忆评测 新颖性/spatial_memory.md>)、[离散环境笔记](<../research_notes/可控操作 轨迹构图 记忆评测 新颖性/discrete_environments.md>)和[记忆与轨迹图笔记](<../research_notes/可控操作 轨迹构图 记忆评测 新颖性/memory_graph_audit.md>)。论文及仓库下载缓存只用于本地核查，不是拟发布文档。

**投资判断：如果主要创新就是“用模拟器约束操作，让实际执行自动生成地点—通勤图”，现有证据不支持围绕这个主张开发完整新 benchmark。** R2R 已经通过合法动作确定地点转移，并直接记录有序访问路径；TextWorld 明确从动作规则构造转移系统；IVLN 已对跨任务实际路径自动评分；GOAT 已比较自主探索所得记忆的保留与清空。你的方法相对自由编程工作区确实更容易得到可靠、可审计的行为表示，但这是已有模拟环境的设计优势，不是独有构图机制。**本次没有发现完整复刻“连续自由探索、独立原生 agent session、自产持久记忆、地点通勤图、四维测量”的一篇论文；这不等于已经确认 novelty。** 若继续，贡献必须由完整评测协议新增的测量能力及实证结果支撑。没有证据要求你另发明记忆算法，也没有证据足以保证目前的组合已构成充分贡献。

## 你的约束发生在模拟器中，不是提示中

你的意思是：游戏只接受规定的操作，程序检查其前置条件、执行效果、更新世界，并判断目标完成。agent 可以自由探索，但不能靠任意代码改变游戏状态。雪地到山谷是否可走、耗时多少、失败后位置是否改变，都由环境决定。**这比要求 agent 在提示里“按指定流程行动”强得多，也不等于给 agent 指定正确路线。** 此解释是对当前方案的忠实形式化，不把它改成其他研究问题。

可以把环境当前位置读取函数记为 \(p\)，实际第 \(t\) 步的地点为 \(v_t=p(s_t)\)。这里 \(s_t\) 只是模拟器当时的完整记录，不要求成为你评测图的节点。地点变化时生成独立通勤边：

\[
e_t=(v_t,v_{t+1},t,\Delta t,\text{当时条件})\qquad v_t\ne v_{t+1}.
\]

同一通路走三次就保留三条边，序号保存行走次序。`雪地→山谷→雪地→森林` 可以确定地转成有序有向多重图，也能从该记录恢复位置序列。**转换确定，不代表 agent 决策确定，也不代表环境没有随机过程。** 天气可以使用作者知道、agent 不知道的任意预录时间表；评分不能把未来天气当作 agent 应知信息。

“雪地和山谷两个节点”准确表达的是地理投影，而非只有两种完整游戏状态。同在山谷，工具、时间和天气可以不同。原地测量、等待和渡河失败可能都不产生通勤边，必须保留访问事件和反馈记录；无需把这些因素全部扩张为新节点。评价侧私有证据账本只记录实际交付的证据，不把隐藏规则、未见地点或标准答案注入 agent 的记忆。独立 session 之间只有其自行生成的声明持久内容传递，地图成果也不能成为未经声明的历史通道。

这一设计解决的是**位置行为的可观测与可复现表示**。它尚未自动解决“是否使用记忆”的归因：两条相同路线可能分别来自记忆、当前观察或偶然选择；一条更短路线也可能漏掉必测目标。四维判断仍依赖任务关系、实际经验、完成质量及记忆对照。

## 直接先例来自导航与规则游戏，不只来自记忆 benchmark

**R2R 是对构图原理最直接的反例。** 模拟器以采样地点组成导航图，动作只能选择当前允许到达的位置，并确定地更新位置。官方 rollout 逐次追加地点，不去重；评测代码检查相邻地点是否合法并累计距离。它没有以多重图容器命名，但这些有序日志能直接转换成你的表示，换容器不产生额外行为信息。R2R 本身主要研究单任务指令导航，不覆盖你的原生记忆四维协议。（[论文 §3.2–4.4](https://arxiv.org/html/1711.07280)；[固定版本动作执行](https://github.com/peteanderson80/Matterport3DSimulator/blob/589d091b111333f9e9f9d6cfd021b2eb68435925/src/lib/MatterSim.cpp#L501)；[轨迹追加](https://github.com/peteanderson80/Matterport3DSimulator/blob/589d091b111333f9e9f9d6cfd021b2eb68435925/tasks/R2R/agent.py#L219)；[合法性及距离计算](https://github.com/peteanderson80/Matterport3DSimulator/blob/589d091b111333f9e9f9d6cfd021b2eb68435925/tasks/R2R/eval.py#L47)）

**IVLN 更接近“连续任务中的经验与路径评分”。** 多个指令任务构成同场景 tour，agent 在执行中累积局部环境知识，t-nDTW 自动比较实际与参考路径，限制不同任务间的配对。它不是只看终点。但训练／验证协议在任务间有 oracle 移动，失败后还可带去正确终点；正式隐藏测试去掉到目标的 oracle，仍保留去下一起点的移动。被动观察这些过程的历史不能统称完全自主采集。其地图或隐状态跨任务累积，也不同于无上下文的原生 LLM session。（[正文及附录 B](https://arxiv.org/html/2210.03087)；[固定版本 phase 与 oracle](https://github.com/jacobkrantz/IVLN-CE/blob/14417fc0930fc273183667c09e3e3564adc823a0/ivlnce_baselines/common/environments.py#L234)；[路径评分](https://github.com/jacobkrantz/IVLN-CE/blob/14417fc0930fc273183667c09e3e3564adc823a0/habitat_extensions/tour_ndtw.py#L94)）

**GOAT 已经包含自产空间记忆和保留／清空对照。** 一段 episode 连续给多个目标，agent 通过受限移动和实际观察建立地图或隐状态；清空记忆的消融检验后续导航效率。实际距离由模拟器位置变化计算，下一任务从实际结束位置计算参考距离。它没有你的独立 session 和四维协议，但直接削弱“别人没有研究自主探索记忆对后续路线的作用”这一主张。（[论文 §3、§5–7](https://arxiv.org/html/2404.06609)；[固定版本 GoatSPL](https://github.com/Ram81/goat-bench/blob/74c41d19d4a4c3608d1575b512087b5a529aee0e/goat_bench/measurements/nav.py#L344)；[隐状态清空](https://github.com/Ram81/goat-bench/blob/74c41d19d4a4c3608d1575b512087b5a529aee0e/goat_bench/trainers/ppo_trainer_no_2d.py#L210)）

**TextWorld 则直接覆盖“规则动作产生合法转移”的基础机制。** 逻辑事实定义状态，动作规则检查前置条件并修改事实；前向推导生成 proof tree，合并重复状态得到转移系统，房间地图本身也是图。你的地点图与其完整逻辑状态图不同，但不能因此说环境动作直接构图此前不存在。（[论文 §3.1–3.2、§5.2](https://arxiv.org/html/1806.11532v2)；[World.from_map](https://github.com/microsoft/TextWorld/blob/main/textworld/generator/world.py#L168)；[State.is_applicable / apply](https://github.com/microsoft/TextWorld/blob/main/textworld/logic/__init__.py#L1692)）

ALFWorld、ScienceWorld、BabyAI/MiniGrid 同样由环境定义操作、位置和合法效果。ScienceWorld 的移动实现检查相连且可通行的 portal，随后修改 agent 所在地点，与你举的地点迁移直接同类。AgentBoard 已利用这些环境自动检查进度、动作合法性和探索，不等于你的通勤图评分，但也不是只检查最后是否成功。（[ALFWorld](https://arxiv.org/html/2010.03768v2)；[ScienceWorld](https://arxiv.org/html/2203.07540v2)及[移动代码](https://github.com/allenai/ScienceWorld/blob/main/simulator/src/main/scala/scienceworld/actions/ActionMoveToLocation.scala)；[BabyAI](https://arxiv.org/html/1810.08272v3)；[AgentBoard](https://arxiv.org/html/2401.13178v2)）

## 构图、自产记忆和四维测量分别已有近邻

以下比较中的“相同”指机制层面相同，不代表论文完整协议相同。“未定义”只表示所读版本未定义这一项，不是证明其他版本或实现绝不存在。两张表分别比较图表示和记忆协议，避免把内部记忆图与外部轨迹图混为一谈。

| 工作 | 节点／边及生成来源 | 重复、顺序怎样处理 | 图的作用与和你的关系 |
|---|---|---|---|
| **你的方案** | 稳定地点／每次实际通勤；直接读环境日志 | 每次移动独立留边，关联序号和事件 | 外部四维评测；尚未实现验证 |
| [R2R](https://arxiv.org/html/1711.07280) | 地点／合法通路来自环境；实际访问来自 rollout | 实际有序列表保留重访，可直接转多重边 | 同类直接空间轨迹生成；非四维记忆评测 |
| [IVLN](https://arxiv.org/html/2210.03087) | 地点图或连续位置；实际路径来自执行 | 有序路径及 task/phase 标签 | 外部跨任务路径评分；高度相关 |
| [GOAT](https://arxiv.org/html/2404.06609) | 内部地图来自观察；外部距离来自实际位置 | 每步累计移动代价；未定义你的多重图 | 跨目标记忆效率；部分相同 |
| [TextWorld](https://arxiv.org/html/1806.11532v2) | 房间图、逻辑状态／规则转移 | 完整状态图合并重复状态；不等于每次通勤图 | 环境生成与验收；基础机制相同 |
| [EMG](https://arxiv.org/html/2607.13884v2) | 动作三元组／相邻观察；扫描实际及专家轨迹 | 合并相同动作节点；边 occurrence 实现未证实 | 直接 trace 构图后生成内部纠错记忆；对象不同 |
| [Trajectory Graph Copilot](https://arxiv.org/html/2607.27443v1) | 规范化动作／动作连接，观察作属性 | 合并动作，邻接矩阵记连接；重复观察表征平均 | trace 图用于 GNN 错误检测；非四维记忆评测 |
| [MC-EvoBench](https://arxiv.org/html/2610.13829v1) | 任务、资源、条件／需要、产生等预声明关系 | 编译阶段链；实际通过阶段累积信用 | 任务依赖图进度；非逐次通勤生成 |
| [EvoAgentBench](https://arxiv.org/html/2607.05202v1) | 任务／共享能力；LLM 从多条 trace 抽取并审核能力 | 语义合并，非原始移动 occurrence | 定义任务相关性和迁移划分；构图不同 |
| [EMem-Bench](https://arxiv.org/html/2609.28236v1) | 内部实体／空间关系；动作评分另用冻结标注 | 维护关系更新；不是通勤次数图 | ERR 检查经验违背；内部图对象不同 |

| 工作 | 谁产生历史与记忆 | session／持续边界 | 能力及指标，和四维的关系 |
|---|---|---|---|
| **你的方案** | 被测 agent 自行执行、决定保存；私有账本不注入 | 连续任务流，每任务新 session；只留声明原生记忆 | 获取／泛化、保持、纠正、干扰；公式未定 |
| R2R | agent 当前执行；参考路线供训练评价 | 单任务导航 | 成功／导航误差；不覆盖四维 |
| IVLN | 自执行＋任务间 oracle 观察 | tour 内跨任务积累地图／隐状态 | t-nDTW 与导航成绩；非完整原生四维 |
| GOAT | 自执行观察建立记忆 | 同 episode 多目标，保留或重置记忆 | SR/SPL，后续目标效率；非独立 session |
| [AgentCL](https://arxiv.org/html/2606.02461v3) | 明确自主合成经验，无标准正确记忆指导 | 首轮读写、次轮只读；heldout 固定记忆 | PG/SG/GG，塑性、稳定、泛化；最接近部分能力 |
| EMG | 自跑探索＋专家成功轨迹离线建记忆 | train/test 分开，测试记忆固定 | 错误纠正、已见／未见迁移；研究记忆算法 |
| Copilot | 历史轨迹训练错误检测器，在线外部反馈 | 当前任务逐步检查 | 错误检测与恢复；非原生持久记忆四维 |
| MC-EvoBench | source 自执行形成声明产物 | 重置世界和库存，fresh target；source 可写、target 只读 | 主要前向迁移、图进度；非全部四维实证 |
| [MemoryArena](https://arxiv.org/html/2602.16313v2) | 标准循环按自身动作观察更新；长上下文直接保留 | 相依子任务新 session，统一 Retrieve/Update | SR/PS/sPS 与深度；非你的四个行为分数 |
| [PAST-Bench](https://arxiv.org/html/2608.04003v1) | native 持久内容，多数从 learn/update 形成；部分预置参考 | fresh session，匹配 persistence on/off | 保持、更新、陈旧／错误／干扰控制与 trace 证据 |
| [MemTransfer](https://arxiv.org/html/2609.32313v1) | 专家成功示范历史，测试时固定 | 新起点、旧路阻断、混合历史 | SR/SPL、受阻尝试及恢复；非自主历史更新 |
| EMem-Bench | 作者生成历史，系统写入和检索 | 历史 ingestion 后执行，episode-local 库 | ERR、规律泛化、动态更新；非连续自产经历 |

**AgentCL 是必须正面比较的组合先例。** 论文实际在 BabyAI 和 ScienceWorld 做实验，并非仅引用这些环境；agent 自主写经验，评价 plasticity、stability、generalization。这已经结合“受控操作环境＋自产记忆＋相同／相关任务”。其主要评分不是外部位置图，且本次没有代码确认其 session 清理与原生工作区边界完全等同于你；但不能再把自产记忆或离散环境当作它没有的东西。（[v3 §3–4、表 3、附录 B.8/B.13](https://arxiv.org/html/2606.02461v3)）

**EMG 和 Copilot 直接否定“别人的 trace 图都依赖 LLM 抽象”的说法。** 前者先扫描动作观察构图，再匹配公共子图与编辑路径，随后才用 LLM 写指导；后者规范化动作并直接连接序列，再用图模型检测错误。EMG 同时使用专家成功轨迹；Copilot 的错误标签包含 LLM、规则和人工校验，不能说所有评分纯程序且无监督。两者都不等于你的外部地理图，但直接构图这一步已有。（[EMG §4、算法 1–3](https://arxiv.org/html/2607.13884v2)；[Copilot §3、附录 C](https://arxiv.org/html/2607.27443v1)）

**MC-EvoBench 与 MemoryArena 的边界也必须保留。** MC 的 graph.py 从 catalog 关系构图，metrics.py 根据通过阶段汇总编译的 graph_paths；不是移动一次新增一条通勤边。MemoryArena 的历史来自自己的交互，不是统一由人提供正确记忆，但采用共享记忆接口，主要测相互依赖任务的结果。两者不能证明你的整个方案已被复制，也不能因为图对象不同就忽略它们已覆盖的自产经验与跨 session 评价。（[MC 附录 B/C](https://arxiv.org/html/2610.13829v1)及[源码](https://github.com/xzw-ustc/mc-bench-open-source/blob/main/src/mcbench/metrics.py)；[MemoryArena §3–4](https://arxiv.org/html/2602.16313v2)）

## 可控构图是可靠实验基础，不是现成的新增测量能力

你的优势可以据实主张为：环境决定操作语义；位置、通行反馈与代价可以客观记录；相同日志得到相同地理图；不同内部记忆格式的 agent 可以共用外部表示。这些优点与“研究自产记忆的四种能力”直接相关，因为它们减少行为判定的含糊性。但是，**相对自由编程更可靠，不等于相对受控导航和规则游戏更新颖。** 本报告不建议重新使用 SWE-bench；比较它只解释转向新环境的理由。

限制动作也有代价：评价范围收缩为这套接口内的空间与工具行为，不能自然覆盖任意原生工具能力。通勤图对移动精确，但对非移动操作有信息损失。若最后的分数仅为距离、步数和往返次数，有序路径本身就足以计算；必须诚实解释图运算新增了什么，而不是用图容器名称制造区别。

CLS 和 nDTW 已经根据图距离自动比较完整路径，IVLN 更将这一思路扩展到跨任务序列。它们通常评价参考路线一致性，不自动评价记忆；开放制图也不应机械套用。首次探索未知地点可能合理且产生未来价值，评测器的全知最短路可能错罚它。你的四维评价不能强制唯一、知道未来天气的 GT 路径。（[CLS §3](https://arxiv.org/html/1905.12255)；[nDTW §2及附录](https://arxiv.org/html/1907.05446)）

| 主张 | 本次判断及原因 |
|---|---|
| 首次用环境合法操作产生可直接构图的 trace | **不成立**：R2R、TextWorld 已有直接机制 |
| 首次从实际 trace 程序构图，不依赖 LLM 提炼 | **不成立**：位置导航记录、EMG/Copilot 构图已有 |
| 首次用跨任务路径评价自产记忆收益 | **不能主张**：IVLN/GOAT 已有近邻 |
| 首次在离散游戏中评价 agent 自写经验的稳定与泛化 | **不能主张**：AgentCL 有实际实验 |
| 地点 occurrence 图不同于任务依赖图和内部记忆图 | **区别成立**，但区别本身不是充分贡献 |
| 同一连续原生任务流中的完整四维外部评测 | **本次未找到完全同构实现**；不据此宣称首次或充分 novelty |
| 该方法更有效、更准确，或揭示新的能力差异 | **尚无验证**：需要与 SR、成本、路径／局部事件评分比较 |

获取与泛化、保持、纠正、干扰本身是明确研究问题。要继续这个问题，不必证明一种全新图算法，也不必改变目标去增加无关诊断。但在当前证据下，**不应先开发大游戏，随后期待“图＋四维”自然成为贡献。** 只有在任务与评分已经明确，并能证明完整协议测出已有评价遗漏的目标能力差异时，才有证据支持这项新 benchmark 的投入。若主要贡献仍停留在“可控操作生成图”，建议停止这项创新主张；可以保留技术基础，不为保住游戏设定追加模块。

## 阅读审计界定了结论能确定到哪里

## 结论：停止把构图机制当作主要创新，完整协议尚未被判定无价值

这次调查改变了比较对象：最直接的先例不是 MemoryArena，而是 **R2R 的合法地点转移、IVLN 的跨任务路径评分、GOAT 的自主空间记忆对照、AgentCL 的受控任务自产经验评测**。它们让“靠固定操作可控地生成图”这一主要 novelty 主张无法成立。此前只比较任务依赖图和内部记忆图，遗漏了这些直接先例，本报告纠正了这个缺口。

**明确建议：不要以构图方式已足够新为前提继续开发完整游戏。** 四维自产记忆问题可以继续研究，但现有方案尚未展示相对近邻的新测量贡献。未找到全要素同构论文，不能成为继续投入的充分理由；已有构图先例，也不能成为整个研究不可能成立的证明。这个边界比肯定“能发”或断言“完全没意义”更符合目前可核实的证据。
