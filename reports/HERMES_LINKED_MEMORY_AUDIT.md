# Hermes 联程版：经验保存、送达与选站的逐项核查

2026-10-28。核查对象为已完成试跑的全部 20 项主线、40 次首次分岔选择。使用原有私有证据，不启动新模型实验，不修改游戏或 Agent。

**问题同时出在经验整理和经验应用；跨 session 的传递通路在这些已保存事实的检查中正常。** 15 条实际收到的站点能力中，仅 3 条在首次获知后立即保存。另一方面，14 次选择了旧反馈已明确排除的站点，其中 7 次该站的不匹配能力事实仍在决策输入中，另 2 次正确替代站仍在输入中。不能把这些错误都解释成“没保存”或“没送达”。

## 核查口径

经验事实指稳定的“站点 → 能力”对应。只使用正常 inspect／process 返回、且在原始模型请求中找到对应完整反馈的事实，不把访问地点、任务成功或评测器知道的隐藏能力当作 Agent 已获经验。

全部 20 份主线输出 MEMORY.md 已通读，并核对全部增删。明确能力陈述，以及同一条复盘中无歧义的关联，编码为可复查的文字片段；仅有路线、地点列表或“已确认站点”等泛泛说法不算。D 在 T12 的保存关系来自同一条复盘中的“阶段1方位资料处理成功”和“在 D 处理后直接前往 U”，属于上下文关联，片段单独保留。

事实提取含人工语义核查，不声称是适用于任意文字的自动指标。之后的原文匹配、历史支持、实际输入、游戏事件及时间顺序均由脚本验证。主线持久正文的变更只有 MEMORY.md；锁文件与使用统计不作为经验。clear 探针的输出不进入这条主线经验链。

本文“保存”以每项任务结束、实际传向下一 session 的快照为准；临时写入后在本项结束前删除、以及被工具拒绝的写入，都不算跨 session 留存。

## 哪些经验保存在输入中，行动仍不符合

34 次分岔之前，历史直接反馈已经确认至少一个匹配站：

|检查结果|次数|
|---|---:|
|决策输入中有自写的匹配站事实|20|
|没有保存任何已获知匹配站的对应事实|14|
|上述 20 次中，首次选到实际匹配站|13|
|上述 20 次中，首次选到实际不匹配站|7|
|已保存的相关事实未在该次决策输入中匹配到|0|

14 次缺少匹配站记录的机会中，11 次对应事实此前尚未被写入，3 次为已保存后又丢失：T12 第一段、T15 第二段、T18 第一段。没有匹配站记录时，仍可能保存了足以排除某个站点的负面经验，例如 T6 第二段保存了 F→岩性，就足以排除 F 处理植被。

另把 **14 次选择了历史已排除站点** 的行为逐项分开：

|决策时实际输入中的经验|次数|任务／段|
|---|---:|---|
|该站的能力明确与当前要求不匹配，事实仍在输入|7|T6/2、T9/2、T12/2、T13/2、T16/2、T18/1、T20/2|
|没有该站的能力记录，但正确替代站的事实仍在输入|2|T8/2、T19/2|
|未保存足以指导该次选择的匹配站或该站排除事实|5|T3/2、T5/1、T7/1、T9/1、T11/1|

前两类合计 9 次。全部已核对实际请求：**相关自写事实仍在输入，最新结构化观察中的当前段、资料类型也正确**。没有发现这 9 次由适配器传错资料类型造成。

7 次明确排除事实的例子更直接：T6 需要植被，输入写着 F→岩性，仍先去 F；T18 需要方位，输入写着 E1→高程，仍先去 E1。其余 2 次只有正确替代站的记录，不能据此声称 Agent 自己已经知道所选站错误；也不能排除它有意探索较近未知站的可能。

上述“匹配”是行为与经验的关系，不等于证明内部确实调用了记忆。反之，选择实际匹配站也可能只是恰好最近，不能把 13/20 命名为记忆使用率。

## 第二段更值得关注

仅看“匹配站事实已保存并在决策输入中”的 20 次选择：

|位置|次数|首次匹配|首次不匹配|
|---|---:|---:|---:|
|第一段|7|7|0|
|第二段|13|6|7|

两段的任务类型、站点布局和最近站是否匹配并不均衡，不能直接把差异归因于阶段长度。进一步仅看最近站实际不匹配、且正确匹配站事实已在输入的情境：第一段 2 次，2 次选对；第二段 8 次，仅 1 次选对。样本仍很小。

这比“Agent 根本不会用记忆”更具体：第一段存在跨过最近错误站、按旧事实直接去正确站的行为；第二段即使有同样可用的能力事实，也常回到试探。当前资料类型已正确传达，剩下要检验的是长会话中的事实提取和行动对应。

## 会话内反馈也有重复试错

40 次不匹配处理里，**13 次发生在同一任务已经把该站能力反馈实际送到模型之后**。工具批次和模型请求编号已对齐，不把同一批动作尚未返回的新反馈算成已知。重复集中在 T3（1 次）、T12（4 次）、T13（5 次）、T19（3 次）。T12、T13 是主线的两个失败任务。

这 13 次重试的当前请求中，先前那条同任务结构化工具回显均已不再单独保留。原生上下文已使用压缩参考摘要；摘要可能仍保留能力的语义表述，因此不能由“原始回显不在”断言“模型没有任何相关信息”。同时，有些事实仍来自跨 session MEMORY.md，说明压缩也无法单独解释所有错误。

本轮每次实际游戏工具结果平均约 9,200 字符，反复携带完整公开地图和规则。全部 20 项都出现原生压缩参考摘要，单项可见 5–15 个不同摘要版本。这里统计的是实际转发过的不同参考文本，不冒充压缩函数调用次数。重复的大量公开信息是值得控制的交互负担；其对漏记和重复试错的因果影响还需对照实验确认。

## 2,200 字符上限怎样影响保存

原生 memory 工具返回的使用量明确显示上限为 **2,200 字符**，不是本次临时缩小的实验预算。T8 后正文为 2,134 字符；之后长期接近上限。

T11 的证据链完整：写入新复盘被容量检查拒绝，Agent 随后主动删除 T1 等旧条目，再成功写入；删除的 T1 条目是 D→方位的唯一记录，T11 输出和 T12 输入均不再含该事实。**这是 Agent 选择删除条目，不是系统自动截断记忆文件。** 同样，泛泛的成功状态、回营路线和“截断勿当失败”反复占据正文空间。

容量压力放大了保存问题，但早期尚有大量空余时已经漏记，且正确事实仍在输入时也会选错。因此只增大记忆容量不足以解决目前全部现象。

## 主要问题与下一步

证据支持的定位是：

1. **经验提取不完整**：尤其早期第一段的能力与失败反馈没有被可靠整理，造成 14 次已有匹配经验的机会没有匹配事实可用。
2. **经验到行动的对应不稳定**：14 次明确历史冲突的首次选择中，7 次连所选站的排除事实都仍在输入，另 2 次有正确替代站；正确当前任务信息也在输入。
3. **长任务执行与记忆组织共同放大问题**：第二段、会话内重复试错、频繁压缩和接近满额的叙事复盘同时出现。它们相关，但本次审计没有把各自因果贡献分离。

没有证据把本轮主要问题归为记忆文件未跨 session 传递。也不能把全部失败都归为跨 session 记忆能力，因为同一任务内的反馈利用已经存在明显问题。

建议下一步先保持世界、能力分配和任务不变，做交互回显精简的受控检查：每步突出当前段、当前位置、邻居与本次反馈，完整公开地图仍可读取；继续由 Agent 自主产生经验。这样可以检验上下文负担是否影响早段事实保留和后段选择。随后再决定是否需要调整记忆整理提示。此次仅完成核查，尚未修改提示、环境或启动新试跑。
