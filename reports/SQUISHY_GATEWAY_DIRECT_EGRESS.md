# Squishy 更换隧道后的模型网关排查

日期：2026-10-25（工作区本地日期）。

已修复模型请求 502。故障发生在网关向模型服务发起请求时，不是本次美国隧道的入站转发。

## 证据

- 网关、Claude Code 网页、benchmark 服务均在监听。公网域名能到达网关，网关能识别当前客户端凭据。
- benchmark 保存的加密凭据与网关现行远程连接配置相同，没有密钥不同步。
- 网关 `.env` 仍为 `CHATGPT_PROXY=http://127.0.0.1:6268`，但 6268 无监听；旧 Boost 可执行文件也已不存在。已有代理启动任务因旧程序路径失效而失败。
- 不带凭据直连模型与认证服务，分别得到 HTTP 401 和 HTTP 200，说明当前网络可以直接到达。
- 使用网关原有代码、现有登录状态和明确关闭的出站代理，成功取得七个模型别名，包括 `gpt-5.6-luna`。

隧道承接的是“客户端 → Squishy 网关”，这次失败的是“Squishy 网关 → 模型服务”。换美国隧道不会自动清除进程中单独配置的旧出站代理。以上证据不能确定 Boost 在何时、因何被移除，也没有据此推断用户迁移的操作顺序。

## 变更与验证

先备份 `.env`，只将 `CHATGPT_PROXY` 改为空值，让现有网络代码直连，再通过原计划任务重启模型网关。没有更改 API key、模型别名、隧道配置、证书、Windows 系统代理、benchmark 服务或 Claude Code 网页服务。

私有备份在服务器 `C:/Agents/SubscriptionGateway/data/direct-egress-repair-20261026-023718/`，包含修改前后配置；目录名称使用服务器本地时间。
