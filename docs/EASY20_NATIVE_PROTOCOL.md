# Easy20 首轮原生 GA 试跑约定

当前网页使用[联程巡测](EASY20_LINKED_MAP.md)；下一轮实验选择 `--design memorybenchmark/data/station_easy20_linked.json`。每封有两段，仍在同一个 loop 完成后收尾；该地图默认主阶段模型调用上限 100、收尾上限 6，旧地图默认 40／6。两段要求同时保留在当前任务提醒中，最新反馈另报当前段与完成数。以下保留首轮单段流程及历史预算。

本轮使用 `655339f` 的独立源码快照与 `lanting-easy20-v1`，同一轮世界分配由宿主私有抽样，与 Agent 随机种子独立。被测主体为原生 GenericAgent，网关模型别名为 `gpt-5.6-luna`。

## 执行与干预

- T1 为真实前缀；T2–T20 各运行保留记忆主线与当前任务清除探针，共 39 个有效 session。
- 每项全新原生进程、空对话和空工作状态。保留分支使用此前主线自主生成的原生 memory，清除分支恢复完整原版基础 memory。
- 每个探针从对应主线任务执行前的实际历史检查点分叉，其行为和新记忆不推进主线。
- 每项最多 18 次游戏操作、40 次实际主阶段模型调用、6 次任务后整理调用。普通循环返回可以在同一会话续跑，预算不重置。
- 游戏失败或预算耗尽保留为实际结果。基础设施中断独立归档，从原任务开始前状态恢复，不重跑已完成的有效分支。
- 完整请求、响应、原生工具调用、通勤与节点反馈、输入／输出记忆清单和源码指纹私有保留。网关凭据仅在宿主中解密使用。

## 分析约定

报告全部 20 项委托的主线与对照，包括失败。路程、移动次数、查询、处理失败、与已交付证据重复的查询分别统计；任务失败时不把未走完的低路程当作节省。

固定展示 T3、T17 的配对执行图：它们分别是任务目录中首次回到 AB 站群、以及该组最长间隔后的委托。选择依据为任务安排，全部其他会话仍进入总表与全任务图。

获得反馈、保存经验、经验出现在当前模型输入、行动与经验一致分别核对。相关经验机会由实际交互史决定，不按任务编号预先授予。单条短路线或一次配对路程差异不能代替检索／输入证据。

四组能力的大地图采用描述性分析，不调用小原型的昂贵精确策略搜索。未计算的最优策略参考显式为 `null`，不以脚本策略冒充精确最优值。

```powershell
python -m scripts.audit_station_native --run <私有运行目录> --output <新的审计结果.json> --source-commit 655339f --source-newlines crlf
python -m scripts.analyze_station_native --run <私有运行目录> --output <新的分析目录> --skip-exact-references --trace-tasks T3 T17
```

冻结源码在 Windows 的归档中使用 CRLF。审计同时保留真实字节哈希，并显式按 CRLF 核对 Git 提交内容；不修改正在运行的文件。完整审计逐事件重放各分支，核对主线／探针历史、记忆链、空上下文、隔离与实际模型调用预算。

这是单个私有世界、单条自主历史的开发试跑；十九个不同任务上的探针不作为十九次独立重复实验。结果用于检查环境是否产生可追溯的记忆行为材料，后续再组织重复实验和能力测量。

分析器已使用此前 15 个真实 session 回归：全部行为和记忆输入描述量保持一致，763 个累计事件记录逐一重放通过。本轮 39 个有效 session 已完成，全部 5,174 条累计事件记录重放通过，见[完整结果](../reports/EASY20_NATIVE_GA_PILOT.md)。
