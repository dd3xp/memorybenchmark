# 保留／清除分支并行

同一个 agent 每次最多执行两个隔离会话：当前任务的保留分支与清除分支。每个会话仍按一次模型响应最多一个游戏动作、一次移动只到一个相邻地点运行。GA 与 Hermes 各有独立实验，因此两者合计最多四个会话并行。

## 实验语义

任务 n 的两个分支从保留历史在任务 n 开始前的同一份环境检查点分叉。保留分支载入自己此前自主形成的记忆；清除分支载入原生初始记忆。二者拥有独立游戏对象、可写记忆副本、隔离进程、MCP 服务和日志。

两组都结束后，任务 n+1 只继承保留分支的环境与记忆。清除分支的行动、发现和记忆不会进入后续保留任务。保留任务之间依然按顺序执行；清除组不是一条独立演化的长期历史。

界面分开的两个运行项表示条件分别展示和记录。它们的会话、可写记忆和游戏实例隔离，外层调度器与主线检查点共享。准确的实验单位是一条自主保留历史及其逐任务清除对照，不能据此声称进行了两条独立的长期重复实验。共享调度器的记录错误会影响运行进度，无法由此推断发生了跨组记忆传递。

第一个任务的两组都没有历史经验，单列为无历史控制。跨 session 比较仍使用 T2–T20 的 19 对任务。原生 agent 代码、提示、地图、模型、预算、精简反馈和评分规则不因调度变化而修改。

## 继续已有运行

调度实现为 `memorybenchmark.prototypes.station_parallel`，读取既有 `pilot.json`、冻结的设计和原生基础库，恢复保留历史，复用已完成的会话。调用前必须确认原调度器已经退出，当前没有同一实验的其他所有者。

```powershell
python -m memorybenchmark.prototypes.station_parallel `
  --output .runs/pilot-example `
  --base-url https://your-model-gateway.example `
  --distro Ubuntu `
  --runtime /path/to/native-runtime
```

网关凭据仍只通过父进程的 `MEMORYBENCH_GATEWAY_KEY` 环境变量传递，原生工作进程无法读取。Hermes 还需提供它原有的运行时依赖挂载参数。

调度器在启动前校验原冻结文件的哈希，记录补充调度代码的哈希及已完成会话。每对任务最多启动两个工作进程；仅协调线程写入 `pilot.json`，结果按任务及分支排序，保持现有重放审计的格式。`scheduling.jsonl` 记录分支开始、结束和任务起点指纹。

## 当前实验的边界切换

2026-10-31 的固定地图两轮实验保留原始 `a1681f7` 代码和调用前计划，额外安装调度模块。切换器先记录已完成会话的内容指纹，再预留下一个尚未打开的会话目录；旧调度器的独占目录创建会在此处停止，正在执行的会话照常结束并保存。确认旧所有者和工作进程退出后，切换器仅释放自己预留的空目录，再启动并行恢复。

这是有记录的调度迁移。预留目录不作为游戏会话显示，不产生模型调用、游戏动作或图边。原始退出记录、边界校验、补充代码及串行／并行执行区段分别保留；不会将切换前的数据冒充为并行运行。

如果某项任务已有一个有效分支，只补跑缺失分支，从下一个完整任务开始成对并行。游戏失败也是有效结果，不会因此重跑；只有已识别的传输故障允许有限恢复。发生一组故障时，另一组先正常结束并保存，再恢复失败组。

## 软件验证

[验证记录](assets/paired-parallel/validation.json)包含服务器 210 项回归检查，以及两种原生 agent 的并行契约。契约使用固定响应，同时启动两个真实隔离工作进程，分别写入不同的合成记忆，并完成完整两段委托；核查进程重叠、记忆分离、动作反馈和单步边界。两组各 30 次操作、路程 35，真实模型调用为零。这些是软件验证数据，不能作为 agent 的能力成绩。

测试还覆盖同一任务起点、仅继承保留历史、传输失败时复用已完成的另一组、有效游戏失败不重跑，以及切换目录内出现真实数据时拒绝清理。

[实际切换验证](assets/paired-parallel/live-validation.json)记录现有两轮在 UTC 2026-10-31 21:36 的状态：GA 已保留 9 个有效会话并补跑 T5 清除分支，Hermes 已保留 10 个有效会话并在 T6 两组同时收到模型响应；两轮的冻结内部实现、相同任务起点和输入记忆链核查通过。此文件是当时的运行快照，不是最终成绩。

## 失败记录与已完成分支恢复

2026-10-31 的 Hermes T11 保留分支遇到模型网关 502 后，调度器打印进度时直接读取仅成功会话具有的 `content_changed`，触发 `KeyError`。另一组随后完成并写入完整结果，但协调线程已离开结果收集循环，导致这一组未登记到 `pilot.json`。自动恢复归档失败组后遇到这份未登记目录，按原先的保护规则停止。

修复后，失败结果的进度日志允许可选字段缺失。恢复时若发现未登记目录，须验证它已完整结束，重放全部动作和反馈、核对轨迹图、相同任务起点、输入与输出记忆、完整模型响应、原生会话隔离以及单步动作边界，才登记原结果。验证不通过或结果不完整时仍停止，不删除目录、不盲目重跑。

回归测试模拟真实失败结果不含 `content_changed`，验证另一组仍能正常登记；还覆盖已完成结果补登记，以及轨迹被修改时拒绝接收。[T11 实际保存结果验证](assets/paired-parallel/saved-peer-validation.json)确认清除组原有 52 次操作、路程 56、63 次模型调用可直接保留，验证本身没有模型调用。

运行中的正常会话继续使用各自冻结代码。恢复器仅在原所有者退出后安装修复，保存修复前后的调度代码和指纹，沿用原有恢复次数限制；Agent、游戏、提示与输入记忆不修改。

GA T18 后续出现两组同时连接中断，旧协调器遗留的是未登记的失败结果。恢复器现也可处理这种情况：核对相同任务起点和输入记忆，重放部分动作与图，确认缺失的最后一个模型响应、宿主传输错误审计和反馈指纹，再将该尝试作为基础设施故障归档并从任务起点重试。它不会把部分执行登记为成功，也不继承这次中断后的临时记忆。缺少宿主错误证据时仍拒绝自动恢复。[实际部分轨迹验证](assets/paired-parallel/partial-peer-validation.json)与 214 项回归覆盖这条恢复路径。
