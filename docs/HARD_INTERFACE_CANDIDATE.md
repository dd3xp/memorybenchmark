# Hard候选：中间结果的兼容性

状态：2026-11-16已接入真实游戏、原生执行器与严格审计；第一轮Hermes／Luna校准正在运行。用户明确授权最多两轮，每轮retain／clear各12项，合计最多48项。未替换正式Hard36，未加入实验创建菜单，也不修改任何既有冻结实验。Lunatic继续暂缓。完整结果落地前，不声称已经形成难度梯度。

目标是让已有经验的**选择与组合**影响首次处理和试错成本。允许Agent通过补救完成任务，不以人为压缩上下文、降低预算或不可恢复的陷阱制造任务失败。

## 当前饱和点

当前Hard的所有编目站都产出同一种`catalogued`状态。同一资料的一个可用编目站与一个可用核验站，可以任意组合。奥尔恰24个组合阶段共有384个局部有效实体站对，384个都可接通。学会两张表以后，组合并没有增加适用条件。

只增加局部例外或收窄反馈，仍然可能变成一张更长的表，因此不将它们单独当作解决方案。本候选保留两段独立的委托，只改变**每段内部**两种处理结果是否兼容。

## 一个完整例子

以下是种子61301的真实原型轨迹，代号不是正式地图的资料命名。

| 正常计分委托中的阶段 | 完成任务得到的事实 |
| --- | --- |
| T1第一段：采集资料甲，交付F877编目结果 | P17能把原始资料甲编成F877 |
| T8第二段：取得已编成F877的资料甲，交付标准Ⅰ核验结果 | P02能接收资料甲的F877并产出标准Ⅰ |
| T13第一段：采集原始资料甲，交付标准Ⅰ核验结果 | 应组合P17→P02 |

P24也能成功编目资料甲，但产出F180。选择P24→P02时，第一步反馈是“处理成功，产出F180”，第二步反馈是不支持；资料甲并没有完成目标。不是多走一步就自动算组合成功。

T13的第二段重新取得另一份资料并完成自己的要求，不使用第一段的样本、格式或结果。没有不计分的学习题、研究者写入的记忆或失败后补发的经验。

公开规则需要事先说明：编目有不同中间规格，核验站可能只接受其中一种；同型实体站仍然等价，世界规则在整次运行中固定。反馈只给本站对本份样本的操作、输入、输出与成败，不再附上本站对所有资料的能力表。格式与站点代号独立打乱，不能靠编号单双数或资料序号猜答案。

处理失败不消耗现有样本。编出不适合目标的格式后，可以返回采集点重新采集，再选择另一条链；保留所有尝试和路程，不能把重新采集当成一次新的首次机会。该补救动作已经接入StationGame和原生MCP交互，旧协议保持原行为。

## 分配与计分

候选采用6类资料，每类2种中间规格和2种最终核验标准。这里改变了资料数量与处理契约，不把它包装成原Hard36的同一设计。

- 12条编目经验：资料＋目标中间规格。
- 12条核验经验：资料＋输入规格＋目标标准。
- 每条完整经验2次单独使用、2次组合使用：48个单操作阶段、24个双操作阶段，总计36项、72阶段、96次必需操作。
- 前12项都是正常完成的单操作委托。第一次组合前，两条相关经验都安排在更早的委托中；计划遇见不等于实际获得反馈，更不等于保存或使用了记忆。

报告同时保留局部首次处理成功、面向目标的首次处理正确、整个阶段首次完成、最终任务成功、失败处理与重新采集成本。局部“processed”不能替代面向目标的正确性。未尝试的必需操作留在分母中。新指标不能直接冒充旧Normal／Hard指标的同一口径；对照也必须按同一目标判定规则计算。

8个预先列出的机制种子均满足经验分配与先前机会约束。由评价器完成普通委托后，精确保存反馈的诊断程序可以正确完成24/24组合。这证明任务可解，也说明**本机制仍可能被Luna学成满分**；它不是难度梯度已成立的证据。

另有相同任务、代号、站点和反馈字段的对照，仅关闭核验站的输入规格检查。枚举“知道目标对应核验站，但没有绑定中间规格”的48个站对选择：放宽对照48个可接通，严格候选24个可接通。这是选择空间的计数，既不是随机策略实跑，也不是模型正确率。另一个固定私有世界仅交换编目输出，所有公开委托保持相同，但正确组合不同；当前要求本身不能推出私有配对。

只检查了奥尔恰。沿用当前道路与采集点时，36项均有352步以内的参考路线，最大62次动作；41/48实体站有严格最短路线用途。对候选采集点分配作单独评估后，仅交换15个阶段的采集点、保持各采集点出现总次数不变，可以让48/48站有严格路线用途，最大参考动作仍为62。这个分配作为提案保存在评估文件，**没有写回地图**。无需据此扩大地图或增加道路，也没有批量调整亨比、吴哥或Normal。

上述8种子统计和站点路线投影属于机制检查，不是模型成绩。另已用完整StationGame逐项执行校准序列，确认所有组合都可仅凭此前正常委托实际反馈的事实完成，参考路线在原352步预算内；这个确定性检查仍不代表Hermes成绩。

## 进入正式Hard之前

候选已作为独立协议接入采集／处理、玩家可见文本、实际反馈机会计数和原driver最终严格审计。新分析器只使用当前样本反馈；未调用旧协议的完整能力表推断。原始事件、请求、响应、未知usage与失败尝试均保留，封存后本地校验不再重放游戏。

校准继续使用Hermes、gpt-5.6-luna、注册表实际上下文272000、primary high、单步移动与原科学预算；retain／clear独立基线与历史，记忆只由Agent自己产生。开发样本用于淘汰方案，最终选定规则后在预先保留的世界／顺序上确认，所有尝试均记录，不能挑一个低分种子当结论。

暂定验收目标是重复操作首次正确率70%—90%，相对当前Normal的描述性参照至少低10个百分点，同时保持能从完成任务中积累经验。该区间是待检验的校准标准，不是预测成绩。主结果另列组合整个阶段首次正确率及首次遇见之后的分母，避免只增加首次探索来压低总分；如果仍接近满分，就淘汰这个候选。现有Normal采用多步移动，不能作为与候选单步移动的严格匹配因果对照；同候选的放宽规格对照只改变兼容规则。

启动授权独立记录在[校准范围](../config/authorized-hard-calibration.json)，不扩大原六组或启用任何已作废64k参照。第一轮使用种子61301、两类资料、12任务／32次必需操作；2026-11-16 03:11 UTC之后已确认两组真实模型响应、primary high、272000上下文及游戏动作。每条件自己的原始baseline，retain只继承自己的新记忆，clear每项复原baseline。

## 第二轮选择与重叠条件版本

在第一轮retain完成原审计、归档和退出0后作筛选，clear继续独立运行。若至少6个此前两条事实都实际反馈过的组合中，首次整段正确率仍达到95%，或没有足够这种组合，则第二轮使用预留种子61401的重叠条件版本；否则以独立资料／世界确认第一版。该筛选是开发决策，不是显著性检验，也不自动批准正式地图。

第一版有潜在简化：规格代号全局唯一，模型可能把资料适用条件压平成简单查表。重叠条件版本让F-1／F-2在不同资料中复用，同一个站型对不同资料可能产出不同规格、同一输入规格可能对应不同核验标准。有效经验必须包含资料和输入范围。每种资料有两组可替代编目站型、两组可替代核验站型，规则固定，站型仍各有两座等价实体站。

完整版仍36任务、72独立阶段、96次必需操作，但采用12类资料、48条目标范围经验，每条单独1次、组合1次；前24项全是正常计分委托，后12项每段各有两次处理。96条正向能力绑定并非都安排学习，只保证每个组合所需至少一条有效链有先前正常任务的反馈机会。校准子集为4类资料、8项普通委托＋4项双组合委托。它尚未被批准为正式Hard；不能把更改后的经验分配说成原来每条4次的同一方案。

两版都仅评估奥尔恰，不批量修改其他地图。第一版候选采集点交换已用于独立校准文件；生产地图道路和目标分配不变。第二版先沿用奥尔恰原采集点，未因需要更低分而扩大地图、缩减预算或改动上下文。
