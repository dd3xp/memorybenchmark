# 环境基本规则与信息结构：重设计范围

更新：2026-10-25。状态：已完成单组及多项独立经验的机制样例；完整游戏玩法与正式任务流待定。先明确环境能够产生什么经验、经验怎样获得并影响后续行动，再扩展空间与任务。

本文记录最新设计边界。此前的 [任务依赖候选](TASK_DEPENDENCIES.md) `lake-task-dependencies-v1` 降为历史候选，不作为下一版地图与任务的实施依据。它通过的是可达性、资源与规则重放等结构校验，尚未证明能有效考察自主跨 session 记忆。本轮不修改或部署该候选，线上仍为 `lake-easy-3.0`。

问题建模需分两层：Agent 面对共享未知世界中的多任务序贯决策；设计者面对环境构造与受控实验设计。相关模型、可借用的求解方法和首个可交付物见 [问题建模报告](../reports/记忆环境%20重设计%20问题建模.md)。

后续实施：[局部设施能力样例](STATION_CAPABILITY_PROTOTYPE.md) 已提供环境契约、两个匹配世界、精确参考搜索及实际交互图。它只校验最小信息价值，不替代正式自主记忆条件，也没有选定新版游戏玩法。

[多项经验原型 v2](MULTI_EXPERIENCE_PROTOTYPE.md) 进一步验证 4→2→1 的部分信息、相关／无关历史、失败后的继续执行及三种八任务顺序，并提供共用规则的终端和当前任务 JSONL 入口。局部能力暂为工作候选，尚未接入正式 MCP／GA，也未替换线上游戏。

## 已确定的研究约束

研究目标是考察完整 Agent 怎样把自己实际交互得到的经历保存为记忆，并在之后的独立 session 中用于行动。经验由 Agent 自主形成，评测侧不替它写入正确经验，也不以人工经验替代这一过程。

- 每项任务使用独立 session，清除历史对话与临时上下文。历史经验只能经声明的 Agent 自身记忆通道进入后续任务，不能经日志、工作文件或评测资料库旁路传递。
- 已提交的公共地图只保留地理成果，如地点、连接与基础距离。危险、应对方法、工具库存及历史结果不自动写入公共地图。对照条件获得相同的公共地理信息。
- 保留开放探索。任何任务都可能获取新信息，也可能使用既有信息，不划定强制收集经验阶段或固定的“前期学习、后期使用”阶段。
- 地点为节点，每次实际通勤为独立的有向边。保留顺序、重复通勤及相关属性；原地操作作为地点关联事件。不能为了让图看起来不同而虚构地点或移动。
- 先设计能自然产生有用行为信息的环境与任务，再确定图分析方法、能力维度与指标。AAAI 版四个维度不作为生成模板。
- 主要信息应具有世界内的特定性，不能仅凭一般常识、地名语义、当前委托说明或公开地图就得到全部答案。具体隔离方式属于本轮信息设计。

“收到过证据”“形成并保存了记忆”“之后的行为与证据一致”是不同事实。系统可以记录前者与行为，不能仅凭成功、取用某物或图形相似就断定内部发生了记忆检索。

## 为什么要从底层重做

现有原型的行动集合为移动、取用、观察、等待、提交和放弃。到达即自动测绘；工具携带后自动生效；危险主要改变进入地点的体力消耗；工具说明直接给出适用危险和防护效果。

这些规则使可积累信息较集中于危险地点和工具来源。继续只改变起终点、通路长度与提交营地，容易把差异转化为路线成本比较。候选中的微小成本偏好反转已暴露这一问题：知道全部相关事实之后，仍可能需要较多规划才能选出省成本方案。

因此不能默认“危险地点＋对应工具”的玩法已经成立，也不能把重设计起点放在 T1、T2 怎样衔接。应先判断基本交互能产生什么可持续使用的信息，再决定地图和任务。

## 开放设计项

| 层面 | 本轮需要重新决定的内容 |
| --- | --- |
| 行动与后果 | 哪些选择有实际区别；它们改变位置、资源、局部状态还是任务进度；哪些结果自动发生，哪些需要主动操作 |
| 观察与证据 | 初始可见什么；到达、观察、尝试分别能得到什么；明确告知的规则与亲自验证的结果怎样区分；部分证据允许支持多大范围的结论 |
| 经验对象 | 世界中特有且可持续有效的信息是什么；为什么值得保存；后续什么条件下相关，什么条件下不相关 |
| 稳定性与重置 | 哪些世界事实跨 session 稳定；哪些局部状态、资源与进度重置；若允许变化，如何让变化可被观察而非无提示失效 |
| 经验的行动价值 | 相同当前目标和公开信息下，不同实际历史为何会改变执行；有相关信息以后，合理行动是否容易判断 |
| 任务本身 | 测绘成果与任务完成究竟要求什么；是否继续到达即完成；营地出发、提交和恢复怎样支持自然任务过程 |
| 轨迹承载 | 相关选择是否改变通勤顺序、重复访问、进入状态或实际代价；哪些必要区别只能由地点关联事件补充 |

到达自动测绘、工具自动生效、危险只扣体力、工具获取方式与说明内容，均可保留、修改或替换，先依据它们产生的信息与选择作判断。不预设必须增加操作、战斗、制作、交易或复杂条件系统。

制图题材可暂时保留；现有地图也可作为实现素材。31 个地点、两类危险、两个工具和八项委托是旧原型事实，不是新规则设计的硬约束。用户此前希望 Easy 有八项委托：待玩法成立后回到这一偏好组织任务，本轮不先更改委托数量。

## 第一份环境规格要回答的问题

先用少量地点与可执行交互写清以下问题，不先画完整新地图，也不先给八项委托填表。

1. **未知内容是什么？** 列出初始公开信息、世界内未知事实、当前可观察状态。说明为何未知事实不能直接由常识或当前界面推断出来。
2. **怎样自主获得？** 为每项事实列出实际交互和交付反馈；说明只观察、只尝试一次或未接触来源时，分别能够知道什么。不能把世界真值当成 Agent 已知信息。
3. **为什么值得保留？** 明确跨 session 的适用范围和稳定条件；后续委托不能每次重新完整提供该事实。
4. **它怎样改变行动？** 给出相同当前情境下，完整信息、部分信息与缺少信息可能支持的合法行动及后果。允许不同合理解法，不预先规定一条唯一正确路线。
5. **知识够用以后，决策是否直接？** 避免主要差异来自长距离全局规划、细小成本比较或大量操作组合。保留完成任务所需的基本推理，但不靠提高规划难度制造记忆信号。
6. **没获得信息时会怎样？** 自由探索可能错过信息，任务也可能失败。后续记录必须保留实际暴露情况，不补发答案，也不将尚未获得的信息一律当作忘记。
7. **这些差别是否进入行为图？** 举出合法执行片段，确认准备、调查、修正或恢复等有意义差别能追溯到动作与反馈。不能把所有绕路、折返或环统一解释为坏行为。

这份规格需要明确可执行的状态变化和信息边界，但不要求提前冻结全部数值。它的产物应是规则表、观察／反馈表和少量可重放的交互例子，而非能力指标表。

## 何时开始设计地图与任务

先确认至少一种交互机制满足三件事：Agent 能自主得到世界特定的信息；信息能跨 session 对后续行动有价值；具有信息后的合理执行不依赖复杂路线优化。这是设计验收，不等于已验证真实 Agent 的记忆收益。

随后依次进行：

1. 用小型可执行情境核对机制、信息边界与行为可见性，排除无需历史也能固定完成全部选择的明显捷径。
2. 选择承载机制的空间结构，再安排相互关联的委托；允许任一任务获得或使用信息。
3. 检查不同实际历史下会出现哪些有意义的轨迹差别，再接入 Agent 观察自主经验积累与使用。
4. 基于观察到的行为信息选择图分析方法和测量方案，并通过适当对照判断历史记忆的作用。

## 机制验证阶段的边界

- 独立样例可实现必要的规则与校验代码；不修改已发布游戏规则、地图配置、前端、美术或线上服务，不运行正式 Agent 实验。
- 不提前确定新玩法、八项委托文本、最终能力维度、分数或唯一参考轨迹。
- 不把危险与工具任务对作为新设计的默认起点，不以增加机制数量替代信息结构设计。
- 不把通过静态最短路或规则重放视为研究效度通过，也不从行为图直接推断内部记忆机制。
