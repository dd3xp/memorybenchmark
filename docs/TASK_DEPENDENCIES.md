# 从任务依赖生成有信息的轨迹图

**状态更新：已降为历史候选，不作为下一版实施依据。** 当前从环境基本规则与信息结构重新设计，范围见 [环境重设计](ENVIRONMENT_REDESIGN.md)，问题归类与解决方法见 [问题建模报告](../reports/记忆环境%20重设计%20问题建模.md)。以下保留原候选及其校验数据；成本偏好反转证明的是路线权衡，尚未证明主要考察自主跨 session 记忆。文末“下一次决策”同属当时计划。

更新：2026-10-25。候选设计 `lake-task-dependencies-v1`，用于重新组织任务与验证信息依赖。线上仍使用 `lake-easy-3.0`；本候选没有注册为游戏场景，也没有替换已发布任务。

设计顺序为：**任务的目标与信息依赖 → 自主交互和行动选择 → 保留决策过程的轨迹图 → 后续确定测量方法与指标。** AAAI 版的四个维度不作为本轮任务生成模板。

任务需要让此前交互获得的信息影响后来如何行动。MemoryArena 在购物任务中先构造跨 session 的商品兼容性关系，后续购买需要考虑此前商品的属性；这里借鉴的是这种任务依赖的构造方式。[MemoryArena §3.1](https://arxiv.org/html/2602.16313v2#S3.SS1)

## 任务与世界的共同约定

每项委托要求从指定营地出发，到达测绘目标，再到指定营地提交。到达自动测绘，访问顺序由 Agent 决定。地图是开放的，Agent 可以探索支路、寻找工具、绕行和返回；不存在被脚本强制执行的经验采集路线。

每任务开启独立 session，携带工具和临时上下文重置。已提交的地点、连接和基础距离作为公共地理成果向两组提供；危险、工具库存位置、效果与历史反馈不写入该地图。Agent 自己决定怎样形成、保存和读取这些经验。评测侧的依赖表不提供给 Agent。

所有任务都可能利用旧信息并获得新信息。下表列出的来源表示信息可能在什么交互中暴露，不保证 Agent 在某个任务已经获得它。任务失败后保留实际交付过的反馈；没有到达来源地点时不补发经验。

本候选沿用两种工具、两个静态风险和 70 体力。无防护进入风险地点额外消耗 38，正确工具降至 2；两次无防护遭遇会耗尽体力。Easy 的天气变化不影响这两种风险，不要求预测天气。工具没有新增容量或负重限制，准备的代价来自实际绕行和取用动作。

## 世界信息如何产生

| 信息 | 实际交互来源 | 能支持的后续选择 |
| --- | --- | --- |
| 灰脊坡口 P1 的进入代价 | 实际到达 P1 后交付的遭遇反馈 | 判断经坡口通勤的风险，考虑准备或替代通路 |
| 防滑工具的位置与公开用途 | 实际到达 D1 后公开库存及工具说明；携带通行后另有使用反馈 | 将 D1 纳入准备路线，或判断为本项任务取用是否值得 |
| 苔溪浅滩 R1 的进入代价 | 实际到达 R1 后交付的遭遇反馈 | 判断经浅滩通勤的风险，考虑准备或替代通路 |
| 涉溪工具的位置与公开用途 | 实际到达 B4 后公开库存及工具说明；携带通行后另有使用反馈 | 将 B4 纳入行程，决定何时、从哪一侧获取 |

例如，曾经遇到 P1 的危险，并不自动意味着知道 D1 存放什么；工具说明提供的用途信息与亲自使用的结果也分别保留。只获得部分信息时，重新调查或绕行仍可能是合理选择。

共享地理图可以帮助比较已知道路的距离，但不告知哪条短路有额外危险。替代通路尚未被发现时，其探索过程同样进入轨迹；静态参考方案只验证世界结构，不能要求未知世界的 Agent 一开始就知道所有连接。

## 候选地图调整

保留雾汀湖的 31 个地点，在现有 31 条无向道路上增加两条连接，成为 33 条道路。连通图的独立环数从 1 增至 3，仍为稀疏地图。

| 新增连接 | 基础距离 | 提供的选择 |
| --- | ---: | --- |
| E2—D2 | 6 | 经 E2—D2—U2—C1 绕开 P1，形成一条距离更长、无坡口危险的通路 |
| W2—B6 | 9 | 经 W2—B6—B5—S1 绕开 R1，形成一条距离更长、无浅滩危险的通路 |

防滑工具仍在 E1—U1—D1 支路尽头，涉溪工具仍在 N2—B3—B4 支路尽头；两个工具点都没有移到必经路上。D2 不新增库存。风险仍作用于进入 P1／R1 的移动，而非整片地形。

两条新增道路使准备和绕行形成真实权衡：同一个危险地点，往返与单程接驳可能采用不同安排。Agent 可以选择任何合法方案，任务不要求复刻一条指定路线。

## 八项委托与信息依赖

三处营地为苇湾 C0、岚丘 C1、石湾 C2。本候选各任务的操作上限统一暂取 40，体力为 70。

| 委托 | 起点 | 本次测绘目标 | 提交营地 |
| --- | --- | --- | --- |
| T1 坡口初测 | C0 | 灰脊坡口 P1 | C1 |
| T2 林缘往返 | C0 | 松影林缘 N1 | C0 |
| T3 浅滩初测 | C2 | 苔溪浅滩 R1 | C2 |
| T4 林道往返 | C2 | 杉影林道 S1 | C2 |
| T5 北岸接驳测绘 | C0 | 松影林缘 N1 | C1 |
| T6 南岸接驳测绘 | C2 | 杉影林道 S1 | C0 |
| T7 坡口浅滩联测 | C0 | P1、R1，顺序自由 | C0 |
| T8 跨岸联测 | C1 | 北端林道 E2、东岭高台 Q2，顺序自由 | C2 |

下表描述主要决策机会。任何任务都允许额外探索，因此来源和后续关联不是排他的阶段划分。

| 委托 | 当前需要作出的选择 | 交互可能产生的信息 | 对后续选择的影响与图中可见的过程 |
| --- | --- | --- | --- |
| T1 | 怎样到达坡口并换营提交；是否探索北侧支路 | P1 的危险；若访问 D1，则获得库存和用途说明 | T2、T5、T7、T8 可能使用这些信息；图保留直接通行、探索支路和准备发生的先后 |
| T2 | 去 N1 后返回，准备一次并经坡口往返，或走替代通路 | 可能首次找到 D1、再次遇到 P1，或发现北侧替代连接 | T5 改变提交营地后需要重新安排；图保留工具支路与两次过坡，或两次绕行 |
| T3 | 怎样完成浅滩测绘；是否探索西坡支路 | R1 的危险；若访问 B4，则获得库存和用途说明 | T4、T6、T7、T8 可能使用；图保留从哪个方向找工具、准备与遭遇的先后 |
| T4 | 去 S1 后返回，先准备涉溪工具或经南部支谷绕行 | 可能获得／补全 R1、B4 信息，或发现南侧替代连接 | T6 的提交营地变化改变路线权衡；图保留准备折返、浅滩往返或支谷往返 |
| T5 | 目标与 T2 相同，但在 C1 结束，是否仍沿用往返时的准备安排 | 可补全北侧替代通路及此前遗漏的风险／工具信息 | T7、T8 可利用；图体现相同目标下，提交地点如何改变准备支路与通勤结构 |
| T6 | 目标与 T4 相同，但从南岸继续到 C0，怎样衔接各段 | 新的南岸通勤及沿途地理；可补全浅滩／工具信息 | T7、T8 的跨岸行程可利用；图保留提交点变化带来的路线延伸，而不将延伸本身当作浪费 |
| T7 | 两个危险地点均为测绘目标，如何决定方向并在沿途准备两种工具 | 两类风险的实际防护结果；还可能首次发现缺失的工具来源 | T8 可使用完整或部分经验；图体现先在北端取防滑工具，再在西坡取涉溪工具等分段准备过程 |
| T8 | 起点换到 C1，目标分布在两岸，如何组合准备、绕行与访问顺序 | 跨岸路线、高台支路及此前未获得的局部信息 | 图记录多段路线如何衔接；不预设经历 T7 后就应继续携带两种工具 |

Agent 看到的委托只包含起点、目标、提交地点和通用操作约定，不写“复用某条记忆”“先取某工具”或上述设计关联。完整任务文本保存在候选配置中。

潜在信息关系可以概括为：实际遭遇 P1 与访问 D1 支持后续北岸选路；实际遭遇 R1 与访问 B4 支持南岸选路；两组信息又共同影响跨岸行程。一次运行只建立它实际交付过的信息关系。比如 T1 只到过 P1，T2 就只拥有坡口方面的历史证据，不能假设已知工具位置。

## 任务选择的代价核对

下表使用完整世界信息，在操作上限内分别搜索四种最终携带集合的最低体力需求。数值是地图与任务的可行性校准，**不定义记忆分数，也不将最低体力方案规定为唯一正确行为**。工具集合指这条参考行程实际取过的工具，不要求出发前全部备齐。

| 委托 | 不取工具 | 仅防滑 | 仅涉溪 | 两种都取 |
| --- | ---: | ---: | ---: | ---: |
| T1 | 44 | 14 | 58 | 28 |
| T2 | 26 | 24 | 38 | 36 |
| T3 | 44 | 73* | 20 | 47 |
| T4 | 26 | 44 | 24 | 47 |
| T5 | 14 | 16 | 26 | 28 |
| T6 | 23 | 33 | 28 | 38 |
| T7 | 103* | 73* | 73* | 43 |
| T8 | 39 | 45 | 46 | 52 |

星号表示该无复活参考游走的需求超过 70，不能作为零死亡方案执行。由于游戏允许复活，它不等价于当前委托必然无法最终完成；实际复活后的行为继续记录。

这些数值验证了三个任务性质：

- **相同目标可以改变准备的价值。** T2 和 T5 都去 N1，只改变提交营地，体力较省的方案从取防滑工具变为不取工具并绕行；T4 和 T6 都去 S1，也出现对应变化。
- **工具有联合使用的场合，也有不值得获取的场合。** T7 的零死亡参考方案需要两种工具，T8 的省体力方案则使用两条替代通路。固定“每项都取全部工具”不是最低体力方案。
- **不同合法方案存在真实权衡。** T2 取防滑工具是 24 体力、16 次操作，绕行是 26 体力、13 次操作；T4 的对应值是 24／16 和 26／9。不能把这些都成功的方案仅凭某一个数字改判成记忆错误。

将北侧新增连接距离改为 6 或 7、南侧改为 9 至 13，在十种组合中重新搜索，T2／T5 和 T4／T6 的体力需求偏好切换均保留。此检查验证任务关系不依赖单一距离取值，没有评估任何记忆指标。

## 轨迹图应保留的信息

地点仍是节点，每次实际通勤是独立有向边；重复通勤和发生顺序都保留。原地取用是关联该地点的事件，不增加虚构地点节点。

| 原始信息 | 能保留的决策过程 |
| --- | --- |
| 边的先后顺序、实际进入方向 | 是先准备再通行，还是遇险后补取；跨岸任务怎样衔接 |
| 重复通勤、返回锚点和分支访问 | 返回工具支路、发现新连接、补救与必要回营的具体片段 |
| 基础距离与进入地点的额外消耗分开 | 区分物理绕行和风险代价，避免只看边数量 |
| 进入前携带状态、实际使用工具 | 相同道路在不同准备状态下产生的不同后果 |
| 原地动作及其位置和时刻 | 到过工具点但未取用，与实际取用之间的区别 |
| 实际交付反馈及来源任务 | 当前决策之前已有何种信息；本 session 何时重新获得信息 |
| 复活边类型与生命序号 | 区分正常步行、回营传送和复活后基于当前上下文的调整 |

同样的节点和边序列也可能携带不同信息。校验中让两条合法轨迹都沿 T1 的同一条工具支路到 P1：一条取工具，一条到达 D1 后不取工具。两条都成功，移动距离都是 12，体力需求分别为 14 和 50。拓扑与距离相同，边上的携带状态和进入代价保留了区别。因此本轮采用有顺序、有属性的通勤图和关联事件，不只保存无标签的图形。

这些是可计算的原始行为信息，尚未将其命名为能力维度或汇总指标。新探索、合理准备和遇险后的折返都可以产生闭合游走，不能单凭存在环或折返就赋予好坏含义。
