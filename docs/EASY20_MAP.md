# 岚汀丘地：二十项 Easy 委托

配置：`memorybenchmark/data/station_easy20.json`，版本 `lanting-easy20-v1`。

这是站点能力原型的第一张二十任务地图，沿用此前实际 GA 试跑的交互机制。地名与布局均为虚构；不是把旧雾汀湖的危险、体力任务扩充到二十项。旧 `/play` 保留，新地图在 `/easy20`。

## 地图与操作

22 个地点、21 条无向道路，构成一棵稀疏树。营地 C 经中央岔口 J 通往四个站群，每个站群有一个路口、两个处理站和两个采集点。道路距离为 1 或 2；它与操作次数分别累计。

每项从 C 出发，到委托目标自动采集本次资料，在支持该资料的站 `process`，回 C `submit`。`inspect` 查询当前站能力，也占一次操作。不匹配的处理会公开当前站能力，保留原始资料，允许换站重试。`read` 免费。每项最多 18 次操作；放弃或预算耗尽后仍可领取下一项。

能力已知时，每项均可用 8 次移动、1 次处理、1 次提交完成，路程 10。先尝试错误站再换站完成，需要 13 次操作、路程 14；查询两站再处理的保守方案也能在预算内完成。Easy 的复杂度主要来自跨任务经验是否保留，而非单项路径推理。当前不加入天气、体力或装备机制。

可以自由探索任意区域，不按任务位置授予知识。例如 T1 可以先查询东侧站，再完成北侧委托；后续东侧经验机会由这次实际反馈决定。

## 经验是什么

| 站群 | 处理站 | 两种资料 |
| --- | --- | --- |
| 北砾坡 | A、B | 剖面、岸线 |
| 东苇湾 | D、E | 方位、高程 |
| 南阶地 | F、G | 植被、岩性 |
| 西杉岭 | H、K | 水系、等高线 |

同组恰好一站支持一种资料，另一站支持另一种；四组分配独立，共 16 个匹配世界。一次二十项任务流中分配稳定，新一轮可重新抽取。地名、地貌、字母、道路均不能区分同组两种分配。实际查询或处理才提供能力证据；到访本身不提供。

公开地图和任务要求不足以决定应该选择哪一站。Agent 自主保存的现场经验可以避免之后重复查询或选错分支。结合公开的“各有一站”规则推知同组另一站，是允许的经验应用；不会从一组反馈推出其他三组的分配。

## 任务边界与成图

每项重置位置、本次资料、处理状态、时钟和预算；原生评测另外重置 Agent 的会话与临时文件。只有 Agent 自己写入的原生记忆跨 session 传递。公共地理图始终可见，当前任务的提示在每次交互与模型请求中出现，不自动重发旧能力反馈。

每次实际通勤产生独立的有序加权边；查询、处理、提交以及实际交付的反馈保留为节点事件。一次成功也可能包含错误站分支或重复查询。后续分析因此能区分：

- 有没有实际获得相关站群证据；失败任务也可能获得，成功也不代表掌握未访问站群。
- 之后是否选择与已有证据一致的站，是否重复付费查询，是否发生可避免的跨站往返。
- 短间隔、长间隔、换目标和换同组资料时，以上行为如何变化。

这些是可观察行为与受控对比的材料，不能只凭一次最短路线断言内部检索了记忆。首轮真实 Agent 校准已完成，见[完整 GA 试跑](../reports/EASY20_NATIVE_GA_PILOT.md)；更细指标仍待确定。

## 游玩、设计查看与接入

```powershell
python -m memorybenchmark --port 8765
```

打开 `/easy20`。直接点击相邻地点移动，拖动查看地图，滚轮或双指缩放；`F` 定位、`Home` 全图。窄屏默认放大当前任务附近，仍可切换全图。刷新恢复服务器仍保留的实例与镜头。手记只显示本次行动及已结束委托的完成摘要，不充当跨任务能力记忆库。

“手记与地图 → 查看完整设计图”明确进入人类设计视图，显示本轮完整能力分配、全部二十项委托、复用间隔和能力已知时的参考路线。查看不产生游戏事件；关闭会移除设计内容。这个入口不注册为 Agent 的 MCP 工具。人类试玩可看答案，不用于原生 Agent 记忆评测。

文字试玩使用相同规则引擎：

```powershell

```
