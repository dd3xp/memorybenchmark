# 岚汀丘地：四站巡测与就近策略对照

版本 `lanting-easy20-choice-v2`；配置 `memorybenchmark/data/station_easy20_choice.json`。网页 `/easy20` 使用本版。此前真实 GA 试跑的 `lanting-easy20-v1` 保留在原配置 `station_easy20.json`，旧成绩和数据不变。

## 地图与经验

地图为 38 个地点、45 条带权道路，连通图有 8 个独立环路。保留四个站群和二十项交错委托；每组有两个采集点、四个处理站。道路提供短路、环路与不同长度的站点支线；各站群的单项选择仍保持局部、明确，不增加天气、体力、装备或复杂推理规则。地理图从开始公开。

| 站群 | 四个候选站 | 每种资料的匹配站数 |
| --- | --- | --- |
| 北砾坡 | A、B、N1、N2 | 剖面 2，岸线 2 |
| 东苇湾 | D、E、E1、E2 | 方位 2，高程 2 |
| 南阶地 | F、G、S1、S2 | 植被 2，岩性 2 |
| 西杉岭 | H、K、W1、W2 | 水系 2，等高线 2 |

每组有六种均衡分配，四组独立，共 1,296 个匹配世界。一轮内稳定，宿主私有抽取；公开地理、字母和地貌不能确定分配。知道一站的能力不再能推出其余三站。查询和处理都交付实际能力；失败但已经收到反馈仍留下历史机会。Agent 仍须自主保存和检索经验。

每项从 C 出发，到目标自动采集，在任意一个匹配站处理，再回 C 提交。地图位置不代表距离，按道路权重累计。每项 24 次操作；校验覆盖最不利候选访问顺序，最多用了 22 次，保留探索与补救空间。该预算不自动改变模型调用和整理预算。

## 为什么能够识别单纯就近的行为

以从 P 采集剖面为例，四个候选的公开地理成本为：

| 候选 | P 到站距离 | C→P→该站→C 总路程 |
| --- | ---: | ---: |
| A | 2 | 12 |
| B | 3 | 14 |
| N1 | 5 | 15 |
| N2 | 6 | 17 |

到 Q 采集时远近顺序改变：N1、N2、A、B，完成成本仍分别为 12、14、15、17。四个站群采用旋转后的同类结构，原任务的目标和资料组合保持交错。

对于任一固定委托，在全部匹配世界中，最近站恰好有一半匹配、一半不匹配。相同地理与当前要求下，可以只改变隐藏能力，检验行为是否总停留在最近站。每类还有两个合法站，能进一步区分“选择匹配站”和“在已知匹配站中选择成本较低者”。同一类型换采集点后，较合适的站也可能改变，固定复用上次成功站不总是最低成本。

必须同时保留最近站恰好正确的对照：选择最近且正确不能被单次判为使用记忆；选择较远且正确也可能来自猜测或本次查询。实际复用仍需结合历史获证、记忆读写、当前输入及配对重复。

## 部分经验不会被当成全知

评测侧根据真实反馈维护相容世界集合。对每个候选记录 `known_match`、`known_nonmatch` 或 `unresolved`；地图真值不直接代替 Agent 的历史。

若此前只知道较远的 A 能处理剖面，而较近的 N1/N2 尚未确定，选择 A 是使用一个已知可行方案，不能因为私有真值中 N2 更好就判浪费。只有历史已能排除所有更低成本的未知替代时，才输出“历史可证明的最佳匹配成本”；否则该参考为 `null`。预采集探索和本次查询也须按事件顺序分别解释，不把所有站点访问计为记忆错误。

`station_choice.choice_context` 提供候选状态、几何最近集合、最低成本的已知匹配集合与条件参考。`analyze_trace(..., exact_references=False)` 增加首次站点访问描述；它不输出内部记忆使用的结论，也不计算大状态空间的精确未知世界策略。

## 可复核的机制校验

```powershell
python -m scripts.check_easy20_choice --output .runs/easy20-choice-check-new
python -m unittest discover -s tests -v
python -m memorybenchmark.prototypes.station_session --design memorybenchmark/data/station_easy20_choice.json --human --all-tasks
```

校验结果：

- 全部 1,296 世界 × 20 委托，共 25,920 个选择情境，逐项核对最近站匹配／不匹配各 648 个世界。
- 利用四组独立性，逐组穷举六种局部分配及五项委托、两种反馈策略，共 240 次实际完成重放。其他站群保持固定，不冒充所有世界的完整行为穷举。
- 每组两个目标、六种分配、全部 24 种候选访问顺序，共 1,152 次实际查询／处理／回营重放，全部成功，最多 22 次操作。
- 相同真实前缀下，“根据历史排除最近站”和“只用本次反馈、从最近站尝试”均成功，实际路程分别为 15 与 21。原始通勤图与节点事件一起导出；这是脚本校验，不是 Agent 的记忆成绩。
- 局部经验案例验证：获知 A 不会泄露其余三站；已知一个较远匹配站时，不生成全知最短路线惩罚；两份公开初始观察在匹配／不匹配世界完全相同。

旧版 39 个真实 GA session 的 5,174 条累计事件在修改后再次重放一致，历史结果保留。新版尚未运行真实 Agent，原生经验读取和维护问题仍需单独校准。

[完整脚本校验与实际图记录](../reports/data/easy20-choice-calibration-20261027.json) 已公开。本地 140 项回归中通过 134 项，6 项因可选 MCP SDK 或软链接权限跳过；新增六项针对性检查通过。浏览器完成地图点击／键盘移动、错误处理后换站、回营提交、下项重置、手机尺寸和完整设计视图检查。

## 人类查看与 Agent 接入

`/easy20` 的“手记与地图 → 查看完整设计图”显示本轮能力、全部匹配站、每个候选的完成成本和最佳匹配参考路线。读取不产生游戏事件；关闭后移除设计内容。此入口只供人检查，不进入 Agent MCP。

文字和原生 GA 使用 `--design memorybenchmark/data/station_easy20_choice.json`。新旧地图分别保留配置和版本标识，不在旧实验目录上恢复新地图。新一轮记忆从 Agent 原生基础快照开始，不把旧地图的自存经验带入新的能力世界。
