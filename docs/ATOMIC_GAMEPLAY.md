# Agent 游戏交互

新建站点实验中，GA 与 Hermes 均采用 `action_policy=single`、`movement_mode=step`。每次模型响应最多尝试一个游戏动作；`move` 只接受一个相邻地点 `target`，不提供 `path`。收到实际反馈后再决定下一步。运行入口拒绝新建 `batch` 或 `route` 条件；底层兼容代码用于旧运行核验与恢复。

GA 继续通过原生 `code_run` 调用游戏客户端，Hermes 继续使用原生 MCP 游戏工具。宿主维护每次模型响应的动作配额；脚本循环、多个工具调用或新连接不能重置配额。额外动作返回 `decision_boundary` 及最新游戏反馈，不修改游戏状态或累计代价。无效动作尝试也消耗本轮配额；`read` 和原生文件、记忆工具不受此配额限制。两者的上游源码、记忆实现、任务边界和精简游戏反馈保持原有机制。

网页常规名称为 GA、Hermes，不显示“逐步”。历史 GA 批量执行和 Hermes 连续移动实验保留历史标记，避免把不同执行条件的旧成绩混在一起。已有实验仍按冻结代码和配置核验，不改写为新条件。
