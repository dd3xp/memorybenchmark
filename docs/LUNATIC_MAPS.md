# Lunatic：全区域地图上的处理目的与区域选择

2026-11-07，按用户确认实施 `lunatic-01/02/03-v3.1`：保留“归档编目／关联核验”，另加“自然区域／人类聚居区／动物栖息区”的处理地点要求。三张地图覆盖整个斯堪的纳维亚、蒙古及安第斯山系，不再沿用旧版局部路网。此版尚未启动 Lunatic 模型实验。

## 每项任务给出的条件

每项任务仍有两段。每段明确给出采集点、资料种类、处理要求和处理区域。Agent 到指定点主动采集，再选择要求区域内、具有相应处理能力的站；两段完成后回营地交付。采集点的区域与处理区域可以不同，资料领域也不限定处理区域，因此高程资料可以要求到人类聚居区处理。

每图保持16类资料：8类地理、4类动物、4类人文。24种站型各设三座站，在三类区域各一座，共72座。能力由“资料＋处理要求”决定，同型站在三个区域的能力相同；区域是额外的公开地点约束。每种资料在两种处理要求下各有两个支持站型，两种要求的支持站型完全分开。

地图、位置、站型字母、道路权重和每个地点的区域类别公开。地名与字母不编码隐藏能力。两种处理要求的能力表不在开局提供，不强制 Agent 读写记忆。

## 处理反馈

- 在要求区域内主动处理，无论成功或能力不匹配，都返回该站型在**当前处理要求**下支持的全部资料（1或2类）及本次结果；不返回另一处理要求的能力。
- 能力匹配则完成当前段并推进；能力不匹配则保留原始资料，阶段不推进。
- 区域不匹配时，指出要求区域与当前站区域，保留原始资料且不推进；不披露站型能力。计分把它单列为公开区域选择错误，不误当成该站不支持资料的证据。
- 到访、经过、看地图和最终交付不额外揭示能力。成功处理不会一次给出所有站型或所有处理要求的规则。

## 四次曝光与计分

维持每图64项双段任务、128段。只按“资料×处理要求”计数：16×2＝32个组合，各出现四次。区域不增加能力组合，不重置遇见次数；这四次被安排到三类处理区域，每次重复都换区域，第四次返回首个区域。全图三类目标区域的段数相差至多一段。64个采集点各使用两次；精确资料／要求组合的间隔至少12项。

在自然区域已经通过反馈知道某站型能够按当前要求处理该资料，后续去聚居区的同型站就是第二次或更晚的遇见，考察跨区域同型能力泛用。报告仍按32个资料／要求组合列出首次、去首次和第1至4次遇见；区域作为分项另列，不当成新经验类别。计分保留未执行段，后续成功不覆盖第一次处理错误。另记录已有其他区域匹配站型反馈时，是否首次处理就选择该型，以及当前站此前是否未经处理，用于定位真实跨区域迁移机会；这些行为记录不直接证明内部因果使用。

每任务重置对话、位置与工作记忆；retain 使用本组自主形成的持久记忆，clear 使用本组原始基线。能力反馈的实际可用性与完整组合的计划遇见次数分别记录，不据此声称 Agent 内部因果使用了记忆。

## 预算与验收

每项352次游戏操作、400次主模型调用、6次整理调用、604800秒有效时间，与本轮 Hard 一致。基础设施等待的一周窗口单独计时，不占科学有效时间；整 session 自动重跑为0。未增加天气、体力、战斗或工具门槛。

```powershell
python -m scripts.render_lunatic_maps --map scandinavia
python -m scripts.check_lunatic_maps --map scandinavia --output .runs/fresh-lunatic-check
```
