# Hard约60%的完整保留组开发确认

用户于2026-11-16纽约时间要求将难度调到约60%，暂停偏难旧组，并明确选择“跑保留组全量，运行中观察，不合适就停”。本次只启动一个新的36项retain流；不启动clear、不导入校准记忆、不重跑旧任务。此处60%指去掉每类完整目标经验首次计划遇见后的必需操作首次正确率，最终任务成功率另报。

旧61501组在30项已结算时暂停：29成功、1真实游戏失败；全部操作首次12/72，重复操作3/24，已具备两条实际前置反馈的组合整段首次1/12。T31中断现场与费用保留；其原guard确认host_lease_closed，原driver退出，所属计划任务Disabled。这是用户要求的开发停止，T31不计作科学游戏失败。

新候选使用事先固定的61601世界。保留奥尔恰道路、采集点与48座实体站，仍有中间规格兼容、条件复用和当前样本反馈。把12类资料／48类经验各2次，改为8类资料／32类经验各3次：每种资料一个目标采用2次单独＋1次组合，另一个目标采用1次单独＋2次组合，目标分配跨资料交替。总计仍36项、72独立阶段、96次必需操作。前16项是正常计分的普通委托，覆盖所有前置经验；后续组合均有此前反馈机会。没有不计分学习题或第二段依赖第一段。

[授权配置](../config/authorized-hard-target60-retain.json)固定新source中的地图SHA、唯一请求ID、独立原始baseline、Hermes／gpt-5.6-luna／单步／272000上下文／primary high，以及原400＋6调用、352步、一周有效wall和独立一周故障等待。未知故障暂停；真实游戏失败不为分数重跑。未替换公共地图菜单中的正式Hard。

运行时按已提交的任务边界读取原始事件计数，不新增模型调用、隐藏提示或游戏重放。共享计数器与最终报告口径一致。每个观察写入不可变的小型回执；不改运行中规则。预先声明的停止阈值：

| 已有重复操作机会 | 继续观察范围 |
| --- | --- |
| 少于24次，或已知前置事实的组合不足8段 | 不因正确率停止 |
| 至少24次 | 35%—85% |
| 至少36次 | 45%—75% |
| 至少48次 | 45%—75% |

完整结果的目标区间为55%—65%，中心60%；提前停止范围更宽，避免因很小样本追逐单个错误。缺失组合前置反馈时标记设计问题。停止只发生在checkpoint提交后，不打断正在评分的任务；原始前缀、真实失败、费用和未知usage全部保留，不能把被停止的前缀当成完整成绩。完成全部36项时仍由原driver执行完整严格审计和单份归档，不启动第二个finalizer。

这些阈值用于开发筛选，不是显著性检验；单个保留组不能证明记忆的因果效应，也不保证新候选会落在60%。本次只授权并实现这一新的完整候选，后继设计需要独立版本与记录，不能复用请求ID或覆盖旧实验。
