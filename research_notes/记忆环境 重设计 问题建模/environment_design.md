# 记忆环境的底层设计与验证方法

研究日期：2026-10-25。本文是研究笔记，未修改游戏规则、地图、任务配置或正式测量方法。下文严格区分论文已有方法与本项目的设计推断。

## 1. 已有工作怎样让自主行动产生以后有用的信息？

### Takeaway

最值得借鉴的不是再排列一组有依赖的委托，而是先规定：世界有哪些持久、初始未知的差异，行动怎样揭示这些差异，哪些状态在任务边界重置。Alchemy 提供这种环境生成方法；MemoryArena 提供跨 session 的行动—反馈—记忆—再行动协议。二者都没有承诺把记忆与推理严格分离。

### Cited Findings

- Alchemy 的真实编号是 arXiv:2102.02926；正式题名为 *Alchemy: A benchmark and analysis toolkit for meta-reinforcement learning agents*，发表于 NeurIPS 2021 Datasets and Benchmarks。官方仓库还保留早期题名 *A structured task distribution for meta-reinforcement learning*，是同一项目，不能误认成另一篇论文。[论文条目](https://arxiv.org/abs/2102.02926)、[正式论文集](https://datasets-benchmarks-proceedings.neurips.cc/paper/2021/hash/a3f390d88e4c41f2747bfa2f1b5f87db-Abstract-round2.html)、[官方仓库](https://github.com/google-deepmind/dm_alchemy)
- Alchemy §3.1–3.2、附录 A.2：每个 episode 包含 10 个 trial；该 episode 的隐藏 chemistry 保持不变，而每个 trial 的物品实例重新采样。使用药剂会产生可观察后果。§4.1 说明循环状态在 episode 边界清零，trial 之间保留；这与本项目显式跨 session 的外部记忆协议不同。[Alchemy 正文](https://arxiv.org/html/2102.02926v3#S3)
- Alchemy §3.3：symbolic 版本去掉视觉、导航与运动复杂性，保留潜在结构推断和规划。§3.4 的 ideal observer 基于实际历史维护可能的 chemistry，并搜索当前 trial；脚注明确没有求解整个 episode 的全局最优推断。Oracle 则直接获知隐藏 chemistry。[Alchemy §3.3–3.4](https://arxiv.org/html/2102.02926v3#S3.SS3)
- Alchemy §4.2–4.3：作者检查行动已经揭示的信息，并加入 belief state 或完整 chemistry 作诊断；论文明确这些特权输入实验不算正式解题成绩。[Alchemy §4](https://arxiv.org/html/2102.02926v3#S4)
- MemoryArena §3.1：购物任务用产品属性兼容链、干扰候选和额外选择条件构造跨 session 依赖；人工检查有效性。搜索任务检查每个子问题只依赖先前信息，剔除依赖未来信息的序列。[MemoryArena §3.1](https://arxiv.org/html/2602.16313v2#S3.SS1)
- MemoryArena §3.2：每个子任务单独执行，episode 初始记忆为空，后续通过持久记忆获得过去交互的信息。§4.2 同时报告 SR、PS 和适用场景的 sPS，不能概括成只看最终成功。[MemoryArena §3.2](https://arxiv.org/html/2602.16313v2#S3.SS2)、[§4.2](https://arxiv.org/html/2602.16313v2#S4.SS2)
- MemoryArena 附录 C.3：注入先前正确结果与提炼流程的近似 oracle 条件仍会失败；作者也说明真正的 oracle memory 难以定义。这种干预含有额外正确信息，不等同于“仅恢复该 agent 实际获得过的事实”。[MemoryArena 附录 C.3](https://arxiv.org/html/2602.16313v2#A3.SS3)

### Inferences

- **对本项目的归类建议：**它可以建模为具有持久隐藏环境参数、任务边界重置和外部记忆约束的交互决策问题。与 meta-RL 环境设计相邻，但目前不要求训练一个 meta-RL 算法，也不应把“构造跨 session 记忆 benchmark”直接称成“提出 meta-RL 方法”。
- 借鉴 Alchemy 的可枚举生成器、明确 reset 和诊断工具即可；完整复制 chemistry 结构学习、多步组合与规划，会再次让推理成为主要负担。
- 借鉴 MemoryArena 的信息依赖原则，不必复制必须全链成功的强依赖。我们的设计可允许无记忆者重新探索后完成，记忆的收益体现在行动过程，不能以 NOMEM 必败作为目标。
- 对自由探索，应记录“行动实际暴露了哪些证据”，不能将任务完成标签或设计者预期路径当作知识获得标签。失败可能获得了有用证据，成功也可能没有经历某个机制。

### Gaps

- 上述论文不是针对本项目的地理轨迹图测量方法，不能由它们推出本项目已有 novelty，或推出某种图指标可以识别内部记忆使用。
- Alchemy 的跨 trial 循环状态与我们的跨 session 持久库不是同一实验对象。它证明的是一种可分析环境设计方法，而非直接证明我们的 agent 接入与记忆隔离正确。

## 2. 怎样验证信息来自历史，而不是当前提示、常识或额外注入？

### Takeaway

“两个世界隐藏机制不同”本身不够。需要证明：当前公开输入不能区分这些世界，真实历史能够提供区分证据，而这些差异确实改变行动价值；现场免费重读或一个通用免费策略不能消除历史的收益。这是下面提出的设计检验，不是上述论文已经给出的专门定理。

### Cited Findings

- Alchemy §1 用带未知参数的 POMDP 分布表述问题；§3.4 区分依据历史形成信念的 ideal observer 与直接获得世界真相的 oracle。其设计允许分析者计算不同观察历史下的可能世界。[Alchemy §1、§3.4](https://arxiv.org/html/2102.02926v3#S1)
- MemoryArena 的目标是先前交互的信息影响后续行动；附录 C.3 的近似 oracle 分析保留了在信息可用时仍可能存在推理和执行困难的事实。[MemoryArena §3.2、附录 C.3](https://arxiv.org/html/2602.16313v2#S3.SS2)

### Inferences

以下均是对本项目的建议，尚未成为正式玩法或指标。

**先分别定义三类变量。**

| 变量 | 含义 | 跨 session 处理 |
|---|---|---|
| `p` | 公共地理、当前目标、通用操作说明 | 相同条件下各组一致 |
| `theta` | 世界特有的持久机制，例如某类操作在某设施的实际效果 | 同一世界的委托间稳定，新世界可重新采样 |
| `x` | 当前位置、体力、库存、临时机关状态等 | 逐项规定重置或持续，不能含糊 |

单步过程写作 `x_next ~ T_theta(x, action)`，反馈为 `observation ~ O_theta(x, action, x_next)`。这里的 `theta` 不是 agent 的记忆：它是环境真相；agent 只能通过实际行动与反馈获得关于它的证据。

**做一组成对世界检验。**

1. 固定公开地理、当前目标、起点和其他公开条件，构造 `theta_A`、`theta_B`。
2. 检查在某个实际决策点，agent 仅凭当前公开信息不能知道自己处在哪个世界；包括每步提示、地图点亮内容、物品说明和可见反馈，都不能暗中泄露答案。
3. 找到合法的先前行动历史，其反馈能区分相关差异。不能用“设计上有这个节点”代替“该次运行实际接收过这条反馈”。
4. 用小规模枚举比较：相关历史证据可用时，是否存在更好的后续策略；不知道差异但允许调查时，最好的策略能否同样免费达到这个结果。需要检查完整后果，不能只看最优首个动作名称不同。
5. 如果重新调查有代价，代价应体现在真实执行及记录里；不需要设计成不记得就必死或必败。若通用保守策略、免费现场说明或顺路调查已经消除差异，这个机制对历史没有设计上可证的额外价值。

该检验说明相关历史**可能有决策价值**，不说明某个被测 agent 已经自主学习、保存、检索并使用了它。一次猜中不构成记忆使用证据；成对机制、均衡分配与重复样本可以检查是否只是固定偏好。单一固定世界的隐藏事实也可能被长期调参间接泄露。

**避免预训练替代历史信息。** 通用常识可解释规则，但不应替 agent 知道当前世界的具体参数。新世界对机制做受约束的变化，避免地点名字直接暗示答案，检查公开文本在不同机制下是否仍然相同。变化可以符合游戏物理，不必靠反常识惩罚制造难度。要检验的是“这个世界的事实未知”，而不是假装通用知识不存在。

**严格区分正式条件与诊断条件。**

| 条件 | 可以输入什么 | 能说明什么 |
|---|---|---|
| 正式自主记忆 | agent 原生过程产生的持久内容 | 整个 agent 的经验积累与后续行为 |
| 清除记忆 | 同一当前任务与公开条件，移除规定的持久通道 | 对该实验分支中持久信息的依赖；须匹配前史与环境状态 |
| 实际证据恢复，仅作辅助 | 该运行历史中确实返回过的相关原始反馈，保留出处 | 检查信息重新可见后任务是否容易；改变了提示与表示，不能算自主记忆成绩 |
| 完整机制公开，仅作辅助 | 相关隐藏机制的真相，包括可能从未见过的部分 | 检查已知规则下的规划与操作难度；不能当作历史记忆上限 |

“只提供实际曝光的旧事实”也应谨慎：一次模糊失败可能对应多个机制，不能由评测器替 agent 注入唯一正确解释。最稳妥的是恢复原始证据；若做结构化摘要，应保留不确定性与来源，不补充历史中不存在的结论。

如果恢复证据后仍难，说明环境还可能有规划、推理、指令理解或执行瓶颈；如果明显变容易，也不能仅凭一次对照将损失严格拆成“多少记忆、多少推理”。这些能力相互作用，提示长度与表示方式本身也会改变表现。

### Gaps

- 目前没有为候选新规则完成上述成对世界构造和策略枚举，因此不能宣称新玩法已经满足信息必要性。
- 即使清除记忆后行为退化，仍须检查其他持久通道、地图泄漏、工具状态、缓存、运行目录和不同分支随机性，才能解释具体实验。
- 行为与图结构只能给外部证据；它们不能单独证明内部检索或“确实记住”。

## 3. 怎样从底层机制开始，形成可执行的重设计流程？

### Takeaway

先做一个小而透明的环境生成器和机制检查，再设计八项委托。每个候选机制先检验“初始未知、可由行动获知、跨 session 稳定、后来有价值、已知时不难、轨迹有可观察差别”，不要先为四个维度或某个图指标凑任务。

### Cited Findings

- Alchemy 的生成器参数和状态空间可访问，因此可以实现参考策略、分析历史揭示的信息，并以特权输入做机制诊断；MemoryArena 则对跨任务依赖与解的有效性进行构造和人工核查。两者提供的是互补设计工具。[Alchemy §1、§3–4](https://arxiv.org/html/2102.02926v3#S3)、[MemoryArena §3.1](https://arxiv.org/html/2602.16313v2#S3.SS1)

### Inferences

以下是建议的最小工作流程，不是已完成的实现。

1. **环境契约。** 写出动作集合、每个动作的状态后果和反馈；单列 agent 看得到什么、评测器知道什么。公开一般操作规则，但不公开世界特定参数。
2. **持久差异。** 先只放一个可枚举的未知差异。区分世界内稳定、session 临时状态、当前可见条件；不要一开始加入天气、负重、工具、方向和多重危险的交叉组合。
3. **reset 契约。** 决定世界序列与 session 的边界，逐项写明地点、体力、库存、现场设施、已提交地理和 agent 持久库怎样处理。世界参数持续，临时状态重置，需要从规则上有明确含义。
4. **证据账本。** 每次返回反馈记录 `world_id/session_id/step/action/observation/source`。另记该证据兼容哪些机制；不要把收到信息自动标成学会。账本属于分析端，不反馈给 agent。
5. **任务分布。** 机制成立后才安排目标、起点与相遇机会。每项委托可同时产生和复用经验，没有固定学习期/测试期；允许自由探索，不能保证所有运行都接触同样的信息。
6. **低推理检查。** 用已知机制的短参考策略验证操作直接、代价差异明显，避免多个工具组合和细小路线成本逆转。再用“恢复实际证据”辅助条件检查当前任务对被测模型是否仍然过难；这不替代正式自主记忆条件。
7. **失败与再获得检查。** 未曾接触相关证据的 agent 仍应有合法重新探索途径；前任务失败不应让后续委托天然无法评价。分析时分别保留“未曝光”“曝光后再遇”“重新获得后改进”等事实，不用总成功标签代替。
8. **图的信息检查。** 手工构造几种可解释策略，执行到环境里，再比较生成的图。至少保留地点、独立有向通勤边、顺序、状态/成本及必要的节点事件。检查相关行为是否被图压成一样，以及纯制图差异是否掩盖机制差别。此时不规定最终指标。

这里的关键是允许经历不一样，但解释必须依据各自历史。没有接触某个信息的运行，仍能用来研究探索与经验获得；不能当成“忘了这个信息”的证据。

**供后续比较的极简机制模板。以下均未选定。**

| 模板 | 最小未知内容与交互 | 后续可能有的价值 | 主要风险/是否适合地点通勤图 |
|---|---|---|---|
| 固定的局部行动后果 | 一个设施的两种使用方式，实际效果由世界抽样且稳定；一次使用给出明确后果 | 再次需要同类服务时直接选择合适方式，避免重复试用 | 最接近一事实、一选择，推理低；若差异只有按钮点击，则地点通勤图可能完全相同，必须记录节点事件或放弃此模板 |
| 当前条件与局部方式的简单对应 | 只设两种公开可见的当前条件、两种方式，世界中特定对应关系未知；交互揭示一项对应 | 记住遇过条件的有效方式；未遇过条件仍可现场试验 | 可研究适用条件，但初版不要要求通过一项事实演绎未见条件；仍须检查方式差异是否影响真实通行边/代价 |
| 两处设施的持久能力差异 | 两处地理已知的设施各有不同服务能力，能力经实际使用获知，当前目标不重新播报远端能力 | 以后直接去合适设施，少做无效往返；无记忆者仍可逐处调查 | 自然产生通勤图差异、推理较低；主要考察世界事实记忆，可能退化成地点目录，须确认这是否符合研究目标 |

这些模板只展示需要比较的机制层级：记住行动后果、记住条件对应、记住局部能力。它们不是最终任务，也不因“比原版复杂”就更好。尤其要拒绝这样一种情况：为了让图形发生变化，额外强迫折返或惩罚；应由游戏机制本身产生行动后果。

建议首个可交付物是一页环境契约、一个二值未知机制、两个匹配世界、几个最短合法交互脚本及其图导出。它通过信息与规划检查之后，再决定放入现有地图、是否修改自动测绘/自动工具生效，以及怎样扩展委托流。

### Gaps

- 三个模板尚未经过用户选择、游戏性验证、图信息检查或模型运行。本文不选择新玩法，不构造新四维指标，也不宣称这些建议具有论文贡献。
- 尚未确定是否只接受地点通勤图，还是允许带节点事件和状态属性的轨迹图；这项约束会直接淘汰部分看似适合记忆的机制，需在实现前明确。
